Key concept Anti-pattern

Local Tidiness

The anti-pattern: every folder looks reasonable up close, and nobody can say what the system is. Order without orientation.

Every part is neat; the whole is unknowable. Each folder has a sensible name. Each repo has a README. Each schema follows the standard. Zoom out one level and nobody can tell you what the system *is*, what depends on what, or where a given fact actually comes from.

This is the failure mode that hides best, because it passes every local inspection. Audits look at parts. Reviews look at parts. The problem only appears when someone new arrives, or when something has to change across a boundary — and then it appears all at once.

How it forms

Nobody decides to build it. It accretes from reasonable decisions: a folder added where it made sense that week, a service that solved a real problem, a database created for one project. Every step is defensible. The absence is not of order, but of orientation — no layer was ever responsible for saying what the whole thing is.

It also accelerates with generation. AI produces well-formed, locally tidy artifacts faster than anyone can integrate them: clean code, valid models, correct diagrams — each fine in isolation, none of them connected to a picture of the system.

The symptoms

- Work gets redone because nobody could find that it already existed. - Two teams build the same thing and neither is wrong. - Onboarding is a tour given by a person, because no artifact can give it. - The architecture diagram is aspirational; the real one exists only as a shared assumption. - Every question about the whole starts with "well, it depends who you ask."

Why "just document it" fails

The instinct is a big documentation effort — a wiki, an architecture deck, a landscape drawing. These describe the whole *at a moment*, drift within a quarter, and are then distrusted, which makes the next one harder to justify.

The alternative is structural: make each layer able to describe itself, so the overview is assembled from current artifacts rather than maintained as a separate document. That is Maps Everywhere — local tidiness is precisely what it exists to fix. A folder-note per folder, a schema mirror per database, a purpose statement per repo, decisions recorded where the decision happened.

The test

Point anywhere in the system and ask: can this thing tell me what it is, and how it connects? If the answer requires a person, you have local tidiness — order without orientation.
