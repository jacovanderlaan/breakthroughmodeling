Key concept Architecture

Context As Projection

Agent context is generated from the governed model, the way a data mart is generated from the warehouse, and never hand-written per prompt or per bundle. Model the meaning once and project it to every consumer that needs it.

> Agent context is generated from the governed model, the way a data mart is generated from the warehouse, and never hand-written per prompt or per bundle. Model the meaning once and project it to every consumer that needs it.

Ronald Baan calls it the reconstruction tax: every report, every application and now every agent reconstructs what the data means at the point of use. Context files repeat the pattern. A `CLAUDE.md`, a system prompt or an Open Knowledge Format bundle is usually a hand-written copy of meaning that already exists somewhere else, and like every copy it drifts.

Data warehousing solved this shape decades ago: sources feed one integrated model, and the marts are generated from it. Context as Projection applies the same pattern to agent context. The governed model and its metadata form the knowledge plane (Juan Sequeda's term), and every context bundle is a generated projection of that plane for one consumer. Pierre Bonnet's warning about OKF is this principle stated from the other side: knowledge bundles fragment the organisation's knowledge unless they are projections of governed knowledge. Treated as a projection, a context bundle is a delivery like any other, with lineage back to the model and regenerated when the model changes.

The consequence is a working rule: you do not edit the bundle. You fix the model and project again. The test is simple: can every piece of agent context be regenerated from the model? Where it cannot, meaning is held by hand, and it will drift.
